# CBIS-DDSM阶段分支管理规则

生效日期：2026-07-23  
状态：用户已明确确认

## 1. 固定分支层级

本项目采用逐阶段继承、禁止回合并到`main`的分支结构：

```text
main（阶段一至阶段四，v1.0-baseline）
└── phase-5-final（阶段五最终基准）
    └── phase-6-experiments（阶段六实施分支）
        └── phase-6-final（阶段六确认完成后创建）
            └── phase-7-experiments（后续同理）
```

当前权威分支：

- `main`：固定指向`v1.0-baseline`，提交为`d6530e1f7a53fc131e3a15c6b39f7258599a49de`；
- `phase-5-final`：阶段五最终代码、配置、报告和验证结论；
- `phase-6-experiments`：从`phase-5-final`创建的阶段六实施分支。

`origin/HEAD`只是`origin/main`的符号引用，不是额外阶段分支。

## 2. 新阶段的创建规则

开展阶段N时必须按以下顺序操作：

1. 运行`git status -sb`，识别并保护所有未提交或未跟踪的用户文件；
2. 获取远端最新引用，确认`phase-(N-1)-final`存在；
3. 记录上一阶段最终分支的精确提交SHA；
4. 从`phase-(N-1)-final`创建`phase-N-experiments`；
5. 在`phase-N-experiments`中编写并审批本阶段spec；
6. 仅在用户明确批准后实施、训练、commit或push；
7. 阶段验收完成并获得用户确认后，将最终提交发布为`phase-N-final`；
8. 下一阶段只能从`phase-N-final`创建，不得从`main`或未确认的实验提交创建。

阶段六当前已经完成第1至第4步。阶段六尚未形成`phase-6-final`。

## 3. `main`和最终分支的冻结规则

- `main`只保存阶段一至阶段四基线，不接收阶段五及以后代码、配置、报告或交接包；
- `main`的README不得出现对话交接入口；
- `v1.0-baseline`不得移动、重建或覆盖；
- `phase-N-final`是阶段N后续继承的唯一正式起点；
- 最终分支发布后不得重写历史或强制推送；
- 阶段N+1的工作不得反向修改`phase-N-final`，除非用户明确批准必要的文档或治理修正；
- 阶段五及以后不得合并回`main`。

## 4. 分支命名与发布

- 实施分支：`phase-N-experiments`；
- 最终分支：`phase-N-final`；
- 临时规划、README清理或迁移分支默认不长期保留在远端；
- 新阶段可先在本地实施；是否以及何时推送远端必须遵守用户批准；
- 每个阶段分支的README只描述该阶段已经完成的工作、继承关系和真实状态；
- 不得把未运行的实验、未生成的指标或上一阶段指标写成本阶段成果。

## 5. 分支清理

- 删除分支前必须确认其中的有效提交已由`main`、标签、`phase-N-final`或下一阶段分支保留；
- 远端和本地分支必须逐个、按明确名称删除；
- 禁止批量删除分支；
- 不得删除当前检出的分支；
- 不得通过删除分支隐藏失败实验或未记录结果；
- 分支删除属于破坏性Git操作，必须获得用户明确批准。

## 6. PR与合并规则

- 阶段五及以后不得创建以`main`为合并目标的实现PR；
- 如需代码审查，应以相邻阶段分支进行比较，或创建不合并的审查PR；
- 任何PR在关闭、重新打开或合并前，都必须检查自动合并状态和目标分支；
- 未经用户明确批准，不得合并PR；
- 最终阶段分支以已验证的提交为准，不以PR是否合并作为完成条件。

## 7. 交接时必须报告

新对话接手或结束阶段工作时，必须报告：

- 当前检出的分支及SHA；
- `main`、上一阶段final、当前experiments/final的SHA；
- 当前分支从哪个正式分支创建；
- 是否存在未提交或未跟踪文件；
- 是否读取过官方test；
- 本阶段已完成、未完成和未经批准的事项；
- 下一次允许创建或发布的分支名称。

本规则必须与根目录`AGENTS.md`、`docs/HANDOFF.md`和
`docs/handoff_state.yaml`保持一致。
